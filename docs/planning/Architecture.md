# Architecture.md

Defines the stack, the folder structure, the data flow and the privacy design. All other docs use the names defined here. If a name changes, change it everywhere.

## 1. Stack (chosen for a 3 to 4 hour build)

| Layer | Choice | Reason |
|-------|--------|--------|
| Frontend | Next.js (App Router) + TypeScript + Tailwind CSS + shadcn/ui | Team already uses React and Next.js |
| Charts | Recharts | Simple, no extra setup |
| Frontend state | React state + Zustand | Audit results live only in browser memory |
| Backend | FastAPI (Python 3.11) | Same language as ML code |
| ML | PyTorch (CPU) + Hugging Face Transformers | Needed for token log-probabilities |
| Demo models | GPT-2 small family (base, fine-tuned leaky, fine-tuned fixed) | Small enough for CPU |
| Metrics | scikit-learn (ROC/AUC), NumPy | Calibration |
| PDF | ReportLab, generated in memory (BytesIO) | No disk writes |
| Auth | JWT (HS256) with demo users | See Auth.md |
| Database | PostgreSQL, metadata only, optional | See Database.md |
| Hosting | Frontend on Vercel. Backend on the team laptop with a tunnel for the demo, or a small cloud instance if the model fits | Torch is heavy for free tiers. Verify limits before relying on them |

## 2. Two audit modes

| Mode | Needs | What it does | Where it runs |
|------|-------|--------------|---------------|
| Evidence (gray-box) | Local target model + local reference model + candidate records | Record-level memorization score and heatmap | MemGuard API on the user's machine |
| Extraction (black-box) | Any model that can be prompted | Prefix prompts and an extraction chain (F7) | Local model first. OpenAI-compatible endpoint is optional |

Gray-box scoring cannot work through a plain chat API because it needs token probabilities for the target and the reference model.

## 4. Statelessness rules (privacy by design)

1. Uploaded records, model outputs and API keys exist only in process memory or browser memory.
2. The audit result is streamed to the browser. The PDF is generated by posting that result back to `/reports/pdf`. Nothing is kept between requests.
3. The Shield index (salted hashes) is held in a process-memory dictionary with a time-to-live. It is the only server-side state, and it is wiped by `DELETE /session`.
4. No file writes during requests. Python temp files are disabled in audit code paths. A test enforces this (Testing.md).
5. Logs never contain request bodies, record text, model outputs, tokens or keys.

## 6. Naming conventions

- API base path: `/api/v1`.
- Environment variables start with `MG_` (backend) or `NEXT_PUBLIC_` (frontend).
- Feature IDs: F1 to F8. Requirement IDs: FR-1 to FR-9. Limitation IDs: L-A to L-G.
- Risk bands: LOW, MEDIUM, HIGH, CRITICAL. Never invent other labels.

## 7. Key technical decisions

| Decision | Why | Trade-off |
|----------|-----|-----------|
| Local models for gray-box | Needs token probabilities | Customer must self-host |
| Stream results, do not store | Strong privacy story | Refreshing the page loses the report, so download the PDF |
| Own simple loss-difference score as the default, EZ-style score as an upgrade | Works in hours; paper code license must be checked first | Weaker than EZ on hard cases |
| Mock fixtures in the frontend | Riya can build UI without waiting for the API | Must be replaced by the real client before the demo |
| Metadata-only database, optional | Hackathon needs accounts and run history, not content | Extra setup. Skip it if time is short |
